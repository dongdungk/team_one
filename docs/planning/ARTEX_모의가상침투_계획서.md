# ARTEX 모의 가상 침투 계획서

> 목적: 본 계획서는 **본인이 소유하거나 서면 승인을 받은 웹 서버**를 대상으로 하는, 격리된 모의 침투 훈련의 준비·수행·복구 기준을 정의한다.

## 1. 목표와 성공 기준

### 목표

- 웹 서버의 탐지·대응·복구 절차를 검증한다.
- ARTEX 시나리오별 보안 통제(인증, 권한, 입력 검증, 로깅, 경보)를 점검한다.
- 훈련 중 운영 환경과 실제 사용자·데이터에 영향을 주지 않는다.

### 성공 기준

- 승인된 범위와 시간 안에서만 모든 활동을 수행한다.
- 시나리오별 탐지 로그와 대응 기록을 확보한다.
- 훈련 종료 후 서비스·데이터·설정이 기준 상태로 복구된다.
- 발견사항은 재현 가능한 증적과 개선 권고로 정리된다.

## 2. 권한·범위·중단 기준

| 항목 | 확정 내용 |
| --- | --- |
| 대상 자산 | `미정` — 호스트/IP, 도메인, 애플리케이션, API를 명시 |
| 소유·승인 | `미정` — 소유자 또는 승인권자와 승인 기록 |
| 허용 기간 | `미정` — KST 기준 시작·종료 시각 |
| 허용 기법 | 인증·권한·입력검증·설정·로그 점검 등, 사전 승인 목록으로 제한 |
| 제외 대상 | 운영 DB, 제3자 서비스, 외부 SaaS, 다른 테넌트, 실제 사용자 계정 |
| 중단 기준 | 데이터 변조/유출 징후, 서비스 성능 저하, 범위 이탈, 경보 발생 시 즉시 중지 |
| 비상 연락 | `미정` — 담당자와 연락 수단 |

## 3. 권장 구성: 분리된 훈련 환경

```text
[훈련자 워크스테이션]
        |
        | (사설망 / VPN, 제한된 방화벽 규칙)
        v
[ARTEX 제어·기록 환경] ----> [중앙 로그·모니터링]
        |
        v
[격리된 대상 웹 서버]
  ├─ Reverse proxy / WAF
  ├─ Web application
  ├─ Test database (가명·합성 데이터만)
  └─ 애플리케이션·OS·WAF 로그
```

### 필수 원칙

- 운영 환경과 별도 VPC/VLAN·서브넷 또는 완전 분리된 가상 네트워크를 사용한다.
- 인터넷 공개가 필요 없다면 대상 서버에 공인 IP를 부여하지 않는다. 필요 시에는 허용된 출발지 IP만 방화벽에서 열어 둔다.
- 운영 데이터의 복제본을 사용하지 않는다. 반드시 합성·가명화한 테스트 데이터만 둔다.
- 대상 서버·DB·설정의 스냅샷을 훈련 직전에 생성하고, 복구 절차를 사전 시험한다.
- 훈련용 계정은 최소 권한·단기 자격 증명으로 만들고 종료 즉시 폐기한다.
- 시크릿은 소스 코드·문서에 저장하지 말고 비밀관리 도구 또는 환경별 안전한 저장소에서 관리한다.

## 4. 사전 준비 체크리스트

- [ ] 서면 승인, 범위, 허용 기법, 담당자, 중단 기준을 확정했다.
- [ ] 대상의 도메인/IP/포트/API 목록과 아키텍처를 기록했다.
- [ ] 격리 네트워크와 방화벽 허용 목록을 적용했다.
- [ ] HTTPS 인증서와 테스트용 DNS를 준비했다.
- [ ] 최신 보안 패치가 적용된 OS·웹 서버·런타임·의존성을 사용한다.
- [ ] 테스트 데이터만 적재했고, 백업·스냅샷과 복구 절차를 검증했다.
- [ ] 접근·인증·애플리케이션·DB·WAF 로그를 중앙 수집한다.
- [ ] 시간 동기화(NTP), 로그 보존 기간, 경보 수신자를 설정했다.
- [ ] 모니터링 대시보드와 서비스 상태 확인 방법을 준비했다.
- [ ] 훈련 종료 시 계정/토큰/방화벽 규칙을 원복하는 담당자를 지정했다.

## 5. 시나리오 설계 원칙

시나리오는 공격 재현 자체보다 방어 통제 검증에 초점을 둔다. 각 시나리오에는 다음을 기록한다.

| 필드 | 기입 내용 |
| --- | --- |
| 시나리오 ID / 목적 | 예: 인증 실패 탐지 및 계정 잠금 정책 검증 |
| 전제조건 | 대상 버전, 테스트 계정, 격리 상태 |
| 승인된 행위 | 사전 승인된 안전한 검증 단계만 기술 |
| 관찰 항목 | 접근 로그, WAF 이벤트, 앱 오류, 경보, 성능 지표 |
| 기대 통제 | MFA, 비율 제한, 입력 검증, 세션 보호, 권한 분리 등 |
| 중단 조건 | 오류율/지연 증가, 비정상 데이터 변경, 범위 이탈 |
| 증적 | 타임라인, 로그 ID, 스크린샷, 설정 변경 기록 |
| 복구/검증 | 스냅샷 복구, 계정 폐기, 정상 동작·로그 확인 |

권장 검증 범주: 인증과 세션 관리, 권한 분리, 안전한 입력 처리, 보안 헤더·TLS, 오류 처리, 파일 업로드 정책, API 접근 통제, 비밀정보 노출 방지, 로깅·경보·대응 흐름.

## 6. 진행 절차

1. 킥오프: 승인서·범위·연락망·중단 기준을 재확인한다.
2. 기준선 수집: 정상 트래픽·성능·로그 상태를 기록한다.
3. 시나리오 수행: 승인된 시나리오를 하나씩 수행하고, 각 단계 후 영향을 확인한다.
4. 탐지·대응 검증: 경보 생성, 담당자 통지, 분류·차단·복구 절차의 시간을 기록한다.
5. 종료·원복: 테스트 계정과 임시 규칙을 폐기하고 스냅샷 또는 구성 기준선으로 복구한다.
6. 사후 검토: 증적을 정리하고 위험도·개선 담당자·기한을 합의한다.

## 7. 산출물

- 자산·범위·승인 기록
- 네트워크/애플리케이션 구성도와 버전 목록
- 시나리오별 실행 기록 및 탐지 증적
- 이슈 목록(위험도, 영향, 재현 조건, 개선안, 담당자, 기한)
- 복구 확인서 및 종료 체크리스트
- 재시험 계획

## 8. 필요한 정보 및 결정 사항

아래 항목을 제공받으면 이 계획서를 실제 환경에 맞춰 구체화한다.

1. ARTEX가 가리키는 제품/프레임워크의 정확한 이름·문서 링크 또는 사용 목적
2. 서버가 로컬 VM, 클라우드(AWS/Azure/GCP 등), 사내망 중 어디에 있는지
3. 웹 스택(OS, 웹 서버/프록시, 언어·프레임워크, DB, 컨테이너 사용 여부)
4. 운영 서버인지, 별도 훈련 서버인지와 소유·승인 상태
5. 외부 인터넷 공개 필요 여부 및 사용할 도메인
6. 점검하려는 방어 목표(예: WAF 경보, 인증 정책, 로그/SIEM, 사고 대응)
7. 사용 가능한 모니터링·로그·백업 도구와 훈련 일정
