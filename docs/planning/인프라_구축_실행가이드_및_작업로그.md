## 2\. STEP 0: VMware 가상 네트워크 사전 설정 (Virtual Network Editor)

- [x] VMware `Virtual Network Editor` (관리자 권한 실행):

      - [x] **VMnet1 (LAN):** Subnet IP `192.168.10.0` / **Host adapter OFF (Disabled)** / DHCP **OFF (Disabled)**  
      - [x] **VMnet2 (DMZ):** Subnet IP `192.168.20.0` / **Host adapter OFF (Disabled)** / DHCP **OFF (Disabled)**  
      - [x] **VMnet8 (WAN):** Subnet IP `192.168.80.0` / **Host adapter ON (Enabled)** / DHCP **ON (Enabled)**

      > ⚠️ **\[초특급 주의\] VMnet1과 VMnet2의 Host adapter는 무조건 OFF\!**  
>             만약 `Connect a host virtual adapter to this network`를 켜두면(ON), VMware가 내 윈도우 PC에 자동으로 `192.168.10.1`과 `192.168.20.1`을 할당해 버립니다. 이 경우 FortiGate의 게이트웨이 IP(`.1`)와 100% 충돌하여 가상머신들의 외부 통신 및 핑(Ping)이 완전히 마비됩니다. 윈도우는 오직 외부망인 \*\*`VMnet8`\*\*에만 어댑터를 연결해야 합니다.

- [ ] 각 VM의 어댑터 연결 확인:

      - FortiGate VM: 어댑터 3개 추가 (1=VMnet8, 2=VMnet1, 3=VMnet2)  
      - WEB VM: 어댑터 1개 ➔ `Custom: Specific virtual network` ➔ `VMnet2`  
      - DB, Wazuh VM: 어댑터 1개 ➔ `Custom: Specific virtual network` ➔ `VMnet1`

## 3\. STEP 1: FortiGate 경계 방화벽 기본 설정

- [ ] FortiGate 콘솔 접속 (기본 계정: `admin` / 비밀번호 없음 ➔ 신규 등록)

- [ ] 3개 인터페이스 IP 설정:

```
config system interface
    edit port1
        set alias "WAN"
        set mode static
        set ip 192.168.80.10 255.255.255.0
        set allowaccess ping https http ssh
    next
    edit port2
        set alias "LAN"
        set mode static
        set ip 192.168.10.1 255.255.255.0
        set allowaccess ping https http ssh
    next
    edit port3
        set alias "DMZ"
        set mode static
        set ip 192.168.20.1 255.255.255.0
        set allowaccess ping https http ssh
    next
end
```

- [ ] 기본 라우팅(Default Gateway) 등록 (외부 인터넷 통신 출구 설정):

      > 💡 **네트워크 모드별 게이트웨이 IP 선택:**

| 네트워크 모드 | Port 1의 위치 | 게이트웨이(`set gateway`)에 넣어야 할 IP | 설명 |
| :---- | :---- | :---- | :---- |
| **NAT (권장 / VMnet8)** | VMware 가상 NAT 망 | **`192.168.80.2`** | VMware 가상 게이트웨이 주소 |
| **브리지 (Bridged / VMnet0)** | 실제 공유기 물리 망 | **실제 공유기 IP** (예: `192.168.0.1` 또는 `192.168.1.1`) | Windows `ipconfig` 기본 게이트웨이 |

      * **\[경우 A\] NAT 모드 (VMnet8) 사용 시 (기본 매뉴얼 권장):**

```
config router static
    edit 1
        set gateway 192.168.80.2
        set device port1
    next
end
```

      * **\[경우 B\] 브리지 (Bridged) 모드 사용 시:**

```
config router static
    edit 1
        set gateway <실제_공유기_IP>   # 예: 192.168.0.1
        set device port1
    next
end
```

        *(※ 브리지 환경에서 Port 1을 고정 IP가 아닌 DHCP 자동 할당(`set mode dhcp`)으로 받도록 설정한 경우 공유기가 게이트웨이를 자동으로 밀어넣어 주므로 이 과정은 생략 가능합니다.)*

- [ ] DNS 서버 등록 (포티넷 인증 서버 통신용):

```
config system dns
    set primary 8.8.8.8
    set secondary 1.1.1.1
end
```

- [ ] 관리자 세션 타임아웃 8시간 연장 (작업 중 자동 로그아웃 방지):

```
config system global
    set admintimeout 480
end
```

인터넷 연결 핑 테스트:

```
execute ping 8.8.8.8
```

*(5개 패킷 모두 100% 수신 확인)*

- [ ] 웹 UI 접속 및 무료 영구 평가판(Evaluation License) 활성화:

      - 호스트 윈도우 크롬 브라우저에서 `https://192.168.80.10` 접속 (고급 ➔ 계속 진행)  
      - 라이선스 등록 화면에서 **`Evaluation License` (또는 `FortiCare Account`)** 선택  
      - 포티넷 무료 계정(이메일/비밀번호) 입력 후 확인  
      - 라이선스 동기화 완료 후 FortiGate 자동 재부팅 확인 (영구 무료 사용 활성화)  
- [ ] 기본 방화벽 정책(Policy) 및 객체 등록:

      > 💡 **망 간 통신 구조 핵심 팁:**  
>       DB(`10.20`), Wazuh(`10.30`), 직원 PC(`10.40`)는 모두 동일한 \*\*LAN 망(`VMnet1`)\*\*에 있으므로, 내부 L2 스위칭으로 직접 통신하여 방화벽을 거치지 않습니다. 방화벽 정책은 **\[WAN ↔ DMZ\]**, **\[DMZ ↔ LAN\]** 처럼 서로 다른 망 간의 트래픽을 제어합니다.

      ### 📌 \[방법 1\] 웹 브라우저(GUI)에서 마우스로 설정하기 (추천)

      #### ① IP 주소 객체 등록 (`Policy & Objects` ➔ `Addresses`)

      > 💡 **설정 이유 (전화번호부/명찰 개념):**  
>       방화벽 규칙을 짤 때 매번 복잡한 숫자 IP(`192.168.20.10` 등)를 치면 오타가 나기 쉽습니다. IP마다 `DMZ_WEB`, `LAN_DB` 같은 고유 명찰을 달아두어 나중에 방화벽 정책에서 이름만 콕 집어 선택할 수 있게 하고, 향후 서버 IP가 바뀌더라도 이 객체만 수정하면 모든 방화벽 규칙에 자동 반영되도록 관리 효율성을 높입니다.

      * 상단 **Create New** ➔ **Address** 클릭 후 아래 3개 등록 (직원 PC VM 제외로 3개만 필요):  
        1. Name: `DMZ_WEB` / Type: `Subnet` / IP/Netmask: `192.168.20.10/32`  
        2. Name: `LAN_DB` / Type: `Subnet` / IP/Netmask: `192.168.10.20/32`  
        3. Name: `LAN_WAZUH` / Type: `Subnet` / IP/Netmask: `192.168.10.30/32`

      #### ② 외부 접속용 VIP(포트포워딩) 등록 (`Policy & Objects` ➔ `Virtual IPs`)

      > 💡 **설정 이유 (서버 아바타 / Destination NAT):**  
>            공유기의 '포트포워딩' 기능을 엔터프라이즈 방화벽에서는 \*\*VIP(Virtual IP, 가상 IP)\*\*라고 부릅니다. 외부(WAN) 인터넷에 DMZ 웹서버의 진짜 내부 IP(`192.168.20.10`)를 노출하면 보안상 매우 위험하므로, 방화벽이 외부 대표 IP(`192.168.80.x`)를 \*\*가상 분신(아바타)\*\*으로 내세우고 뒤편에서 몰래 진짜 웹서버의 해당 포트로 트래픽을 배달(주소 변환)해 주는 역할을 합니다. (또한 비인가 포트 및 외부 Ping이 원천 차단됩니다.)

      * **VIP 1: 쇼핑몰 웹 서비스용 (8000 ➔ 80\)**

        * Name: `VIP_DMZ_WEB_8000` / Interface: `port1` (WAN)  
        * External IP: FortiGate Port 1 IP (예: `192.168.80.10` 또는 `192.168.80.128`)  
        * Mapped IP: `192.168.20.10`  
        * **Port Forwarding 활성화:** Protocol `TCP` / External port `8000` / Mapped port `80` ➔ OK  
      * **VIP 2: 윈도우 호스트 원격 관리 SSH용 (2222 ➔ 22 ⭐ 쾌적한 원격 관리)**

        > 💡 **추가 이유:** 작은 VMware 콘솔 화면에서 벗어나, 내 윈도우 PowerShell/MobaXterm에서 폰트 확대 및 복사·붙여넣기를 자유자재로 쓰며 편하게 웹서버를 관리하기 위한 관리자 전용 통로입니다.

        * Name: `VIP_DMZ_WEB_SSH` / Interface: `port1` (WAN)  
        * External IP: FortiGate Port 1 IP (예: `192.168.80.10` 또는 `192.168.80.128`)  
        * Mapped IP: `192.168.20.10`  
        * **Port Forwarding 활성화:** Protocol `TCP` / External port `2222` / Mapped port `22` ➔ OK

      #### ③ Wazuh 에이전트 포트 서비스 등록 (`Policy & Objects` ➔ `Services`)

      > 💡 **설정 이유 (방화벽 포트 사전 등록):**  
>           포티넷 방화벽은 `HTTP(80)`, `MYSQL(3306)` 같은 표준 포트는 기본 탑재하고 있지만, **Wazuh 관제 솔루션 전용 포트인 `1514(실시간 보안 로그 전송)`와 `1515(에이전트 인증 등록)`는 알지 못합니다.** 이 포트들을 방화벽에 커스텀 서비스로 미리 알려주지 않으면, DMZ 웹서버에 Wazuh 에이전트를 설치해도 방화벽이 통신을 의심하여 차단해버리므로 관제 로그가 수집되지 않습니다.

      * 상단 **Create New** ➔ **Service** 클릭:  
        * Name: `WAZUH_1514` / Protocol Type: `TCP/UDP/UDP-Lite/SCTP` / Destination Port: `TCP` `1514` (High 칸은 빈칸) ➔ OK  
        * Name: `WAZUH_1515` / Protocol Type: `TCP/UDP/UDP-Lite/SCTP` / Destination Port: `TCP` `1515` (High 칸은 빈칸) ➔ OK  
      * 상단 **Create New** ➔ **Service Group** 클릭:  
        * Name: `WAZUH_PORTS` / Members: `WAZUH_1514`, `WAZUH_1515` 추가 ➔ OK

      #### ④ 핵심 방화벽 정책 2건 등록 (`Policy & Objects` ➔ `Firewall Policy`)

      > 💡 **정책 단순화 (평가판 3개 제한 완벽 대응):**  
>           외부 정상 사용자 및 ARTEX 공격자는 모두 외부 WAN(`VIP 8000`)을 통해 유입되므로 정책 1건으로 통합되며, DMZ 웹서버가 LAN으로 나가는 통신(DB 질의 \+ Wazuh 관제 로그 전송)도 동일한 방향이므로 정책 1건으로 묶어 **단 2개의 정책**으로 완벽하게 인프라를 통제합니다.

      * 상단 **Create New** 클릭하여 아래 2개 정책 차례대로 생성:

| 번호 | Name (정책명) | Incoming (출발 인터페이스) | Outgoing (도착 인터페이스) | Source (출발지 IP) | Destination (도착지 IP) | Service (허용 포트) | Action | NAT | 핵심 목적 |
| :---: | :---- | :---- | :---- | :---- | :---- | :---- | :---: | :---: | :---- |
| **1** | `WAN_TO_DMZ_WEB` | `port1` (WAN) | `port3` (DMZ) | `all` | **`VIP_DMZ_WEB_8000`**<br>**`VIP_DMZ_WEB_SSH`**<br>(둘 다 선택) | `ALL` (또는 `WEB_8000`, `SSH`) | Accept | **OFF** | 외부 쇼핑몰 웹 접속(8000) 및 호스트 PC 관리자 SSH(2222) 허용 |
| **2** | `DMZ_TO_LAN_INTERNAL` | `port3` (DMZ) | `port2` (LAN) | `DMZ_WEB` | **`LAN_DB`**<br>**`LAN_WAZUH`**<br>(2개 동시 선택) | **`MYSQL`**<br>**`WAZUH_PORTS`**<br>(2개 동시 선택) | Accept | **OFF** | 쇼핑몰 DB 쿼리(3306) 및 실시간 보안 로그(1514/1515) 전송 허용 |

      > 💻 **\[관리자 팁\] 호스트 윈도우 PowerShell에서 웹서버 원격 접속:**  
>         위의 VIP 2번과 정책 1번이 등록되면, 작은 VMware 콘솔 대신 윈도우 터미널에서 아래 명령어로 아주 편하게 접속할 수 있습니다:  
>         `ssh -p 2222 ubuntu@<FortiGate_WAN_IP>`  (예: `ssh -p 2222 ubuntu@192.168.80.128`)

      > ⚠️ **주의: Policy 내 NAT는 반드시 OFF\!**

### \[2026-10-25\] \[트러블슈팅\] DMZ 웹서버에서 FortiGate 게이트웨이(192.168.20.1) 핑 실패 및 IP 충돌 해결 (핵심 ⭐⭐⭐)

* **현상:** DMZ 우분투 웹서버(`192.168.20.10`)에서 게이트웨이인 FortiGate Port 3(`192.168.20.1`)로 핑(Ping) 전송 시 `100% packet loss` 발생.  
* **원인 분석:**  
  * 우분투 내부에서 `ip neigh`로 ARP 테이블을 조회한 결과, `192.168.20.1`의 MAC 주소가 FortiGate의 MAC이 아니라 \*\*윈도우 호스트 PC의 VMnet2 가상 랜카드 MAC(`00:50:56:c0:00:02`)\*\*으로 매핑되어 있었음.  
  * VMware `Virtual Network Editor`에서 VMnet2의 `Connect a host virtual adapter to this network`가 켜져(ON) 있어서, VMware가 윈도우 호스트에 `192.168.20.1`을 강제 부여함.  
  * 결과적으로 같은 DMZ 망(`VMnet2`) 안에서 **\[윈도우 호스트 PC\]와 \[FortiGate Port 3\] 간의 중대한 IP 충돌**이 발생하였고, 윈도우 방화벽이 외부 핑을 차단하여 통신이 두절됨.  
* **해결 방법:**  
  1. VMware `Virtual Network Editor`를 관리자 권한으로 실행.  
  2. 격리된 내부망인 \*\*`VMnet1 (LAN)`\*\*과 \*\*`VMnet2 (DMZ)`\*\*의 **`Connect a host virtual adapter to this network` 옵션을 체크 해제 (OFF)** 처리.  
  3. 윈도우 호스트의 불필요한 가상 NIC을 제거함으로써 **FortiGate가 단독으로 `.1` 게이트웨이 IP를 점유**하게 되어 핑 및 라우팅 통신 즉시 정상 복구.  
  4. (원칙 확립: 호스트 윈도우 PC는 외부 인터넷/WAN 역할을 하는 \*\*`VMnet8`\*\*에만 어댑터를 연결해야 함)

    * *해결:* 웹서버 VM에서 `sudo chmod o+rx /home/ubuntu` 및 `sudo chmod -R o+rX /home/ubuntu/sesac_shop_web_php/logs` 실행 후 에이전트 재시작.  
  * *현상 2: Wazuh 대시보드에서 `wazuh-archives-*` 인덱스 패턴 생성이 안 되거나 검색 불가.*  
    * *원인:* OpenSearch 용량 절약을 위해 Filebeat 기본 설정에서 Archives 전송이 비활성화(`archives.enabled: false`)되어 있음.  
    * *해결:* Wazuh 서버에서 `sudo sed -i 's/archives.enabled: false/archives.enabled: true/' /etc/filebeat/filebeat.yml` 적용 후 `sudo systemctl restart filebeat` 완료.  
    * OpenSearch 대시보드 `Index Patterns`에서 `wazuh-archives-*` (Time field: `timestamp`) 등록 완료.
